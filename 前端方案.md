\# DRA 前端详细设计方案



\## 1. 项目定位



DRA 前端是一个面向安全攻防工程师的：



> \*\*AI 驱动 Windows Driver Security Research Platform\*\*



前端不是普通的后台管理系统，而应该体现：



\* 安全研究平台

\* AI Agent Orchestration

\* 实验室控制台

\* 漏洞研究工作流

\* 实时 Agent 执行状态

\* Windows Lab / VM 状态

\* Evidence / Finding 溯源

\* Detection Evaluation

\* Research Timeline



整体风格：



> \*\*专业安全研究平台 + AI Agent Control Plane + 深色工业风\*\*



不要做成：



\* 普通 SaaS

\* 普通 Admin Dashboard

\* 花里胡哨的黑客网站

\* 赛博朋克游戏 UI



应该更接近：



```text

Security Research Platform

&#x20;       +

AI Agent Platform

&#x20;       +

SOC / EDR Console

&#x20;       +

Developer IDE

```

> \*\*你现在负责实现 DRA 前端 MVP。\*\*

>

>

> 2. Project

> 3. Target

> 4. Hypothesis

> 5. Experiment

> 6. Research Run

> 7. Finding

> 8. Evidence

> 9. Detection Evaluation

> 10. Windows Lab

> 11. Agents

> 12. Settings

>

> 所有 Mock 数据必须具有关联关系，例如 Target → Hypothesis → Experiment → Research Run → Evidence → Finding。

>

> Windows Lab 页面必须包含 VM Pool、VM 状态、Snapshot。

> Detection Evaluation 页面必须包含 Coverage、Telemetry Timeline、Detection Result、Baseline / Variant Comparison。

\# 81. 我建议 Kimi K3 的开发顺序



别让它一次性生成整个项目，那样很容易出现“页面很多，但每个页面都半成品”的情况。



按这个顺序让它做：



```text

第一轮

│

├── 项目初始化

├── Layout

├── Sidebar

├── Header

├── Theme

└── Router



&#x20;       ↓



第二轮

│

├── Dashboard

├── Projects

└── Targets



&#x20;       ↓



第三轮

│

├── Hypotheses

├── Experiments

└── Findings



&#x20;       ↓



第四轮

│

├── Research Run

├── React Flow

└── Agent Timeline



&#x20;       ↓



第五轮

│

├── Evidence

├── Detection

└── Windows Lab



&#x20;       ↓



第六轮

│

├── Agents

├── Tools

├── Settings

└── Audit



&#x20;       ↓



第七轮

│

├── 全局 Mock API

├── Loading

├── Error

├── Empty

├── Approval

└── 全链路交互



&#x20;       ↓



最终

└── UI Polish + Bug Fix

```



\*\*这样做出来的前端会比“一次性让 Kimi 生成 20 个页面”靠谱很多。\*\*



而且最关键的是，前端的数据模型现在已经和我们后面的 \*\*LangGraph State / Agent / Experiment / Evidence / Finding\*\* 对齐了。后面真正接 FastAPI 时，不需要推翻前端重写，只需要把 Mock Service 换成真实 API 即可。
